# 修复数学公式渲染容错

## Goal

让助手消息中常见的 `$$...$$` 行内书写形式也能稳定渲染为展示公式，覆盖用户提供的整段中英文混排公式示例，而不削弱现有 Markdown/KaTeX 安全边界。

## Background

- 当前渲染器位于 `frontend/src/lib/markdown/render.ts`，使用 `marked-katex-extension`、KaTeX 与 DOMPurify 的隔离渲染链路。
- 当前代码刻意只接受“独占行的 `$$...$$`”作为展示公式；`render.test.ts` 还明确断言 `Text $$x+1$$ stays text.` 不渲染。
- 用户示例中的展示公式普遍采用同一行的 `$$F(s)=...$$`，且部分闭合 `$$` 后直接衔接中文，因此不会被当前 block tokenizer 识别。这是主要故障。
- 示例中的 `, dt` / `, dx` 在 TeX 中并非语法错误，会显示普通逗号和变量；更规范的微分间距写法是 `\,dt` / `\,dx`，但渲染器不应擅自改写用户公式语义。
- 单美元 `$...$` 示例中的上下标、分式、根式、希腊字母、求和、积分、极限、连乘、组合数和范数均在 KaTeX 支持范围内。

## Requirements

- R1：识别并渲染闭合的 `$$...$$` 展示公式，无论分隔符是否独占一行。
- R2：支持展示公式前后直接连接普通文本（包括中文），并保持前后文本顺序和内容。
- R3：保留现有 `$...$` 行内公式行为。
- R4：代码围栏、行内代码、货币文本和未闭合分隔符不得被误解析为公式。
- R5：继续使用现有的随机占位符、普通 Markdown 严格清洗、`trust: false` KaTeX 渲染及 KaTeX 专属清洗链路；不得扩大普通 Markdown 的 style/SVG/URL 权限。
- R6：无效 TeX 继续回退为可选择、可复制的源码，不得导致整条消息渲染失败。
- R7：加入用户示例形态的回归测试，至少覆盖同一行 `$$...$$`、相邻中文、多个展示/行内公式混排。

## Acceptance Criteria

- [ ] AC1：`拉普拉斯变换：$$F(s)=...$$` 产生 `.katex-display`，公式前的中文仍存在。
- [ ] AC2：`$$...$$泰勒级数：$$...$$` 产生两个展示公式，且中间中文保持原顺序。
- [ ] AC3：用户提供的完整示例中，所有闭合的单美元和双美元公式均产生 KaTeX 输出，没有因分隔符位置而残留为原始美元文本。
- [ ] AC4：独占行 `$$\n...\n$$` 的既有行为继续通过。
- [ ] AC5：行内代码、代码围栏、货币文本、未闭合 `$`/`$$` 的安全回归测试继续通过。
- [ ] AC6：现有 Markdown/KaTeX 安全测试、前端类型检查、lint、单元测试和生产构建全部通过。

## Out of Scope

- 自动把 `, dt` 改写为 `\,dt`，或纠正用户输入公式的数学排版风格。
- 新增 `\(...\)`、`\[...\]` 等分隔符。
- 更换 Markdown/KaTeX 依赖或新增另一条 `{@html}` 渲染路径。
- 修改用户消息的纯文本呈现策略。

## Key Decisions

- 本次将同一行 `$$...$$` 视为展示公式，而不是行内公式。
- 通过收窄且可测试的 tokenizer 兼容输入形态，不通过预处理字符串或放宽 DOM 清洗策略实现。
- 本任务为轻量修复，PRD-only；无需单独的 `design.md` / `implement.md`。
