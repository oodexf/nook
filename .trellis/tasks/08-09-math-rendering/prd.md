# 添加公式渲染

## Goal

让聊天中的助手回答能够安全、清晰地显示常见数学公式，覆盖行内公式与独立公式块，同时保持现有 Markdown、流式输出、安全边界和移动端阅读体验。

## Background / Confirmed Facts

- 前端使用 Svelte 5；助手消息统一通过 `frontend/src/lib/markdown/MarkdownContent.svelte` 渲染。
- Markdown 管线位于 `frontend/src/lib/markdown/render.ts`，当前使用 `marked` 解析，再由 DOMPurify 按显式标签/属性白名单清洗；这是应用唯一允许插入净化 HTML 的位置。
- 助手流式内容也按节流快照走同一 Markdown 管线，终态会立即完成最后一次渲染；因此公式支持可以复用现有路径，不需要新增 HTML 注入点。
- 用户消息目前走 Svelte 文本转义路径，不进入 Markdown/HTML 渲染管线。
- 现有安全测试覆盖脚本、事件属性、危险 URL、iframe、SVG、远程嵌入、畸形 HTML、表单和样式载体。
- 前端质量规范要求当前 Safari 与 iOS Safari 可用、页面不得横向溢出、100 KB 回答保持可交互，且生产压缩后的初始资源目标小于 250 KB；新增依赖必须记录包体影响。
- KaTeX 提供同步 `renderToString`、默认的 HTML + MathML 可访问性输出，以及可关闭抛错和信任能力的配置。`marked-katex-extension` 可把 `$...$` 与独占行的 `$$...$$` 接入现有 `marked` 实例，但仍需引入 KaTeX CSS/字体并扩展 DOMPurify 白名单。
- MathJax 的覆盖面更广，但对本项目的轻量客户端和包体目标通常成本更高；当前首选候选是 KaTeX。

## Requirements

### R1. Formula syntax and scope

- 仅助手消息支持公式渲染；用户消息继续按纯文本转义显示。
- 行内公式使用 `$...$`；块公式使用分隔符各自独占一行的 `$$...$$`。
- 行内分隔符采用保守边界规则：不得把未闭合 `$` 或常见货币文本（例如 `价格是 $5`）识别为公式。
- 第一版不支持 `\\(...\\)`、`\\[...\\]` 等额外分隔符。
- 公式语法不得破坏围栏代码块、行内代码、普通货币文本或既有 GFM Markdown。

### R2. Rendering behavior

- 公式必须复用 `MarkdownContent` 的单一解析与净化边界，不新增原始 `{@html}` 注入点。
- 行内公式应与正文基线和字号协调；独立公式块应有合理留白，并在窄屏上局部横向滚动而非撑宽页面。
- 流式输出中的未闭合公式必须保持可读且不得导致异常；终态到达后应立即显示最终公式。
- 无效或 KaTeX 不支持的 TeX 不得让整条消息渲染失败；失败公式应以带错误样式的 TeX 原文显示，保持可读、可选择和可复制。

### R3. Security and accessibility

- 公式输出必须保持来源隔离：不可信 Markdown 继续经过禁止 `style`/SVG 的严格净化；仅由 `trust: false` KaTeX 生成的片段进入专属最小净化配置，再安全回填到同一个 `renderMarkdown` / `MarkdownContent` 输出边界。
- KaTeX 专属净化只允许实际渲染所需的 HTML、MathML、受限内联布局样式及 SVG/path 结构；原始 Markdown 不得继承这些权限。
- 禁用需要信任的命令/URL 能力，不允许公式绕过危险 URL、样式、HTML、SVG 或远程嵌入限制。
- 默认保留 MathML 可访问性输出；公式区域不应导致流式内容逐 token 播报。

### R4. Delivery quality

- 添加解析、渲染、安全、流式未闭合输入和窄屏布局测试。
- 测量生产构建资源增量；250 KB 门槛按浏览器首屏实际必需传输的压缩 JS + CSS 计算。自托管 KaTeX 字体由 CSS 按实际公式字形/字体按需加载，不计入首屏门槛，但必须单独记录全部字体及全量公式资产体积。
- 不从 CDN 加载脚本、样式或字体；生产容器继续自包含运行。

## Acceptance Criteria

- [ ] `AC-01` 约定范围内的行内公式与独立公式块在持久化助手消息中正确显示。
- [ ] `AC-02` 同一公式在节流的流式快照中不会使渲染崩溃，终态后显示完整结果。
- [ ] `AC-03` 代码围栏、行内代码、普通 Markdown 及约定的非公式美元文本不被误解析。
- [ ] `AC-04` 无效或不支持的 TeX 不会阻断整条消息；失败公式以带错误样式的 TeX 原文显示，且原文可选择和复制。
- [ ] `AC-05` 原始 Markdown 继续经过禁止 `style`/SVG 的严格净化；只有来源可证明为 `trust: false` KaTeX 输出的隔离片段可经过专属最小白名单，且既有及新增公式 XSS 安全矩阵全部通过。
- [ ] `AC-06` 输出包含可访问的 MathML（或经明确批准的等效机制）。
- [ ] `AC-07` 长公式在移动端仅在公式区域横向滚动，页面本身无横向溢出。
- [ ] `AC-08` `check`、`lint`、`test`、生产构建通过；记录首屏实际必需 JS + CSS、全部自托管公式字体和全量公式资产的压缩体积，且 JS + CSS 满足 250 KB 初始传输目标。
- [ ] `AC-09` 运行时不依赖外部 CDN，公式样式和字体由应用静态资源提供。

## Out of Scope

- 所见即所得公式编辑器、公式工具栏或实时预览输入框。
- 服务端生成公式图片、PDF/导出功能、公式编号与跨公式引用。
- 完整 LaTeX 文档、任意宏包或执行用户定义脚本。
- 在本任务中替换现有 Markdown 解析器或净化器。
